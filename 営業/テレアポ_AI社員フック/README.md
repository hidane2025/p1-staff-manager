**v10での転換：社長ルートの冒頭を、祖父江さんの前職に差し替えた。**

祖父江さんは**もともと求人広告の代理店**にいて、そこから「採用しなくても社員は作れる」と気づいた。
**求人広告を売っていた人間が「採用しなくていい」と言う**、という反転がフックそのもの。

> **私、もともと求人広告の代理店にいたんです。**
> **Q 社長、求人出して人が入るまで、早くて3か月くらいかかりますよね。**
> **しかも、採れないこともあるじゃないですか。私、それをずっと見てたので。**
> （一拍）**今、AI社員を作る会社にいます。1体作るのに、数日です。**

| | ✕ 抽象 | ◎ 具体 |
|---|---|---|
| 早い | 業務が効率化します | **採用は3か月、作るのは数日** |
| 正確 | 精度が上がります | **辞めないし、教えたことを忘れない** |
| 人件費 | **人件費が下がります** | **これから1人増やそうと思ってたのが、増やさなくて済む** |

**タグラインを最後に置く。** 冒頭で言うとスローガンだが、前職の話の後だと結論になる。
そして **「人件費が下がります」は言わない** ── 社長でも今いる社員を切る話に聞こえた瞬間に引く。

> ⚠️ **このカードは祖父江さん専用。** 他の人が使うなら「うちの営業が求人広告の代理店から来まして」に変える。

**前職は両ルート共通の入口。分岐するのは結論だけ。**
採用担当に対しても「求人広告の代理店にいました」は出してよい（代理店とやりとりしている人なので
**「この人は分かってる」になる**）。✕なのは**「採用しなくてよくなります」という結論**のほうで、
担当には **◯「◯◯さんに秘書がつく」** に替える。

**具体例は人名を出して1体だけ細かく話す。出すのは「蒔田ユイ（事務・法務・経理）」。**

> **Q 受注が決まった後の書類って、どなたが作られてます？**
> **Q 契約書と請求書と、名簿みたいなのと…一式でどのくらいかかってます？** ← 工数は相手に言わせる
>
> うちに、**蒔田ユイ**っていう事務のやつがいるんですけど。
> ▶「え、社員さんですか？」 → **「AIです。」** ← ★ここで落ちる
>
> 私が言うのは「**受注決まった**」の一言だけなんです。
> それだけで、**契約書と、名簿と、請求書と、スケジュール表が、1時間で全部できてる。**
> しかも頼んでないのに、**「ここの表記が古いので直しました」って言ってくる**んですよ。

**人名で紹介して、相手が人だと思った直後に明かす。** これが「AI社員が12人います」より確実に効く。
**電話で出すのは1体だけ。** 事務は全業界100%で、**担当者本人の仕事そのもの**だから、
社長にも担当者にも同じ球で刺さる。

> ⚠️ **「勝手に始まる」とは言わない。** 蒔田ユイは起動が人（入力が必要）。
> 正しい軸は **「一言頼むだけで、頼んでいないところまで返してくる」** ──
> ChatGPTは頼んだことだけ返す。ユイは契約書の表記の古さまで指摘してくる。**この差は構造的に正しい。**

> ⚠️ **瀬川リサ（営業の下調べ・提案書）は電話で出さない。**
> 相手との商談の準備をAIでやっていると言うと「私への提案も手抜きなんだな」と聞こえる。
> 全12名の正式名簿と、電話で出す／出さないの判定は [04章](04_AI社員カタログ.md)。

**v9での転換：同じものを、相手によって呼び分ける。**

担当ルートの主語が「会社」だったのが敗因（「社長に出す報告資料を作ります」＝ 担当の得が間接的）。
主語を相手にした。→ **「◯◯さんに、秘書を1体つけます」**、そして **「社員さん一人ひとりに1体ずつ」**。

| | 社長に言うとき | 担当・社員に言うとき |
|---|---|---|
| 呼び方 | **AI社員** | **担当秘書** |
| 聞こえ方 | 人を増やさずに済む＝コストが減る朗報 | 自分に補佐がつく＝**純粋に得** |
| 買う理由 | **代替**を買う | **補佐**を歓迎する |
| 禁止 | 社員に言うと「代わりが来る」 | 社長に言うと「増員」に聞こえる |

**能力は偽らない。変えるのは範囲の言い方だけ。** 矛盾しない理由は **秘書を本人が作るから**
（ヒダネは研修の会社なので、受講者本人が自分の秘書を作る → 本人の判断を覚える → 本人の秘書になる）。
**この一文が言えないと台本が全部嘘になる。**

**当日は、ヒダネが今使っている秘書をその場で実演する。**
営業が予定を言い、**実際のGoogleカレンダーに入るところを見てもらう**（確認済み）。

→ アポの言い方は **◎「30分だけ、見てもらうだけでいいので」**。
**✕「作らせてください」**（相手の30分を作業に使う）でも
**✕「専用のを作ってから伺います」**（当日用意できないので崩れる）でもない。

| | 当日できるか | 相手の負担 | 事前準備 |
|---|---|---|---|
| ✕ 作らせてください | できない | 30分作業する | — |
| ✕ 専用を作ってから伺います | できない | 見るだけ | **1件ごとに必要** |
| **◎ その場でお見せします** | **できる** | **見るだけ** | **ゼロ** |

**事前準備がゼロなので、テレアポの本数をいくら増やしても破綻しない。**
そして実演そのものが「**本当に使っている**」の証明になる（＝「社員3人にAI社員12人」の裏付け）。
社長を呼ぶのも「**見るだけ5分**」なので断りにくい。

**見せるのは「予定を言うだけでGoogleカレンダーに入って、当日リマインドする秘書」。**
全職種で成立するので、誰にかけても使える。ただし**機能はSiriでもできるので機能勝負はしない** ——
売り物は「**全員に1体ずつ配って、使える状態にするところまで**」＝ 研修そのもの。
Google以外の相手には**「確認してお答えします」と言う**（できると言わない）。

**そして助成金の制度改正への回答にもなっている。**
2026-08-03改正で「全社員向けAIリテラシー研修」「汎用プロンプト講座」は対象外。
**「自分の職務専用の秘書を作る」＝職務直結**なので、改正後に残る形はこれ（社労士確認は前提）。

**v8での転換：2枚立てにした。**

社長に直接繋がるのが現実的に難しいので、**採用担当ルートを"捨て札"から"正規ルート"に格上げ**して印刷カードを2枚にした。
担当ルートのゴールは受注ではなく、**商談の中で助成金を出して社長を呼び出すこと**（→ [08章](08_社長に繋げる設計.md)）。

| | 社長ルート（カード1） | 担当ルート（カード2） |
|---|---|---|
| 受付での指名 | 代表者名を名指し | **「総務のご担当の方」**（✕AI担当・✕社内システム担当・✕研修担当） |
| 通りやすさ | **低い** | **高い** |
| 呼び方 | **AI社員** ／ 人は採用する時代から作る時代へ | **担当秘書**（AI社員は**職業否定になる**ので使わない） |
| アポの言い方 | 御社の社員を1人、作らせてください | 30分だけ、**見てもらうだけで**いいので |
| KPI | 商談 → 受注 | **社長との商談が設定されたか** |

**優先順位：① 社労士からの紹介　② 社長への直接テレアポ　③ 担当ルート。**
担当ルートは3番目だが、①②が細い間の主戦場になる。

### v8での訂正：担当ルートの入口を差し替えた

初版の入口は「**求人の原稿って、どなたが書かれてるんですか？**」だったが、
**求人原稿は採用担当ではなく求人広告代理店が書いている。** 外れる推測で入ると共感にならない。

→ 入口を「**求人って、代理店さん通されてますか？**」＝ **当たる確認**に変更。
**そして代理店の存在は追い風になる。**

| 事実 | 意味 |
|---|---|
| 代理店に払っている | **媒体費の予算がある会社** |
| 原稿は代理店が書く | **原稿の話は刺さらない**（＋媒体AIとも被る＝二重） |
| レポートは**自社取扱媒体の分だけ** | ハローワーク・直接応募・紹介が入らない |
| 代理店は媒体を売る側 | **「この媒体はやめましょう」と構造的に言えない** |
| 掲載費は代理店側、面接・入社・定着は社内側 | **突き合わせた人がどこにもいない** ← ★穴 |

**ATSがあっても埋まらない。ATSは掲載費を持っていないので採用単価が出ない。**
→ 商品は「**掲載費 × 歩留まり × 定着を突き合わせた1枚**」（→ [06章10節](06_採用担当ルート.md)）

**v7での転換：台詞中心から、質問中心へ。**
短い質問（1行）を会話の要所に散らし、**相手が答えるたびに話が前に進む**構造にした。質問は6問 → **20問**。
ただし1問1行なので、通話時間はv6とほぼ同じ。

| なぜ短い質問を多用するのか | |
|---|---|
| **答えるコストが低い** | 「はい/いいえ」か一言で済む。考えさせない |
| **相手が喋る回数が増える** | 聞き役から当事者になる |
| **沈黙が生まれない** | 沈黙は切られる隙。質問があれば会話が続く |
| **答えで台本が分岐する** | 決め打ちの営業トークにならない |

> **ただし尋問にしない。2〜3問聞いたら、1つ自分の情報を返す。**
> そして**誘導のために聞かない。本当に知りたいから聞く。**

**新設した STEP 3「AIの温度を測る」（Q3〜Q5）が効く。**
「使ってる」相手に基礎から説明するとバカにされたと感じ、「使ってない」相手に専門用語を使うと置いていかれる。
**3問で分かるなら、聞かない理由がない。**

```
Q3 社長、AIって使われてます？
   使ってる      → 「何に使われてます？」話が早い
   使ってない    → 「ですよね。うちも去年まで全然でした」警戒が下がる
   よく分からない → 「ほとんどの方がそうです」否定しない
```

**v6での転換：**
① 自己紹介を「**弊社、社員を作ってる会社です**」に変更 ── **人材紹介との誤解をわざと誘発し、訂正で驚かせる**
② アポを「12人お見せします」から「**御社の社員を1人、作らせてください**」に変更

| v5（見せる） | v6（作る） |
|---|---|
| 「12人が何やってるか全部お見せします」 | 「**御社の社員を1人、作らせてもらえませんか**」 |
| 相手は**見学者** | 相手は**当事者** |
| 持ち帰るのは印象 | **持ち帰るのは動くAI社員そのもの** |
| 断る理由：「忙しい」で足りる | 断る理由：**探しにくい** |

そして「説明を拒否する」ステップをアポ打診に統合した。
**「電話だと説明しづらいので、作らせてください」**で、拒否がそのまま提案に変わる。

**v5での転換：**着地を「引き継ぎ・教育」から「**採用しなくてよくなる**」に変更。
あわせて、**相手に質問して話させるパートを1問から6問に増やした**（相手7割を目指す）。

```
うち、人が足りなくなったら、AI社員を1人作るんです。
採用しないので。
        （一拍）
人って、採用する時代から、作る時代になったなと思ってて。
```

**「採用する → 作る」。動詞が1つ変わるだけ**なので理解が速く、対比が鮮やかで記憶に残る。
そして**この言い方は誰も傷つけない。**「人を減らす」は敵を作るが、「人を作る」は増やす話なので社長の側に立っている。

**引き継ぎ・教育の切り口は捨てていない。** 採用が刺さらない相手（人を育てるのが経営、と言う社長）への
第2の球として [03](03_刺さる業務カタログ.md) に残してある。

なお「**電話では商品を売らない**」という原則はv1から変えていない。

## 球として使える5条件

| # | 条件 | 満たさないとどうなるか |
|---|---|---|
| 1 | どの業界にもある | 業種ごとに台本を作り直すことになる |
| 2 | 社長が痛みを知っている | 受付を突破できない・決裁が動かない |
| 3 | 「AIでできるの!?」の意外性がある | 「AIで効率化」と同じ扱いになり、聞き流される |
| 4 | ヒダネが実際にやっている | 見せてくださいと言われた瞬間に終わる |
| **5** | **既存ツールの標準機能と被っていない** | **「うちもうやってます」で信用ごと失う** |

<a id="条件5"></a>
### 条件5が抜けていたのがv2の失敗

```
社長「それ、うちのATSがもうやってますけど」
     ↓
この電話だけでなく、ヒダネという会社の評価が下がる
```

条件3（意外性）が欠けているだけなら「刺さらなかった」で済む。
**条件5が欠けていると「何も調べずに電話してきた人」と判断される。損失の質が違う。**

無料ATS（Airワーク採用管理、リクナビHRTech、Hirehub、yoiwork 等）が普及しており、
**応募者への自動返信も面接の日程調整も標準機能**。20〜100名の会社でも既に解決済みの可能性が高い。

→ 既存ツールとの被りチェック表は [03_刺さる業務カタログ.md](03_刺さる業務カタログ.md)

## 結論：7つの設計判断

### 判断① 「AI社員」という単語を、正面から打ち出す

#### なぜこの単語が刺さるのか

**「AIツール」「AI導入」「業務効率化」は聞き飽きられている。** 相手の頭の中に既に棚があり、そこに入れられて終わる。

**「AI社員」には棚がない。**

| | |
|---|---|
| 「AI」も「社員」も、単語としては誰でも知っている | → 危険ではない・怪しくない |
| でも「AI社員」という組み合わせは知らない | → **意味が分からない** |
| しかも「12人」と数えられる | → **ツールは数えない。社員は数える** |

> **既知と未知の差が適度なときに、人は一番知りたくなる。**
> 完全に未知だと無視される。完全に既知でも無視される。
> **「単語は分かるのに、組み合わせが分からない」が最適。**

電話の目的は理解させることではない。**「よく分からないけど聞いてみよう」を作ること。**

#### ただし境界は守る

| | |
|---|---|
| ◯ | 「うち社員3人しかいないんですけど、**AI社員が12人いまして**」→ 事実の提示 |
| ✕ | 「AI社員を導入しませんか」→ **商品の輪郭が曖昧なまま話が進み、商談で崩れる** |

**打ち出すのは単語と具体例。売るのは次の30分だけ。**
そして「AI社員」は比喩なので、**聞かれたら「実体はAIです。人格があるわけじゃないです」と正直に言う。**

---

#### 具体例がないと、単語だけでは死ぬ

「AI社員が12人います」の直後に抽象的な説明をすると、**その瞬間に「AIで効率化」の棚に入る。**
だから**名指しで1〜2体**を出す。スキル定義から実体を特定できた8体：

| 体 | 一言（電話でそのまま使う） |
|---|---|
| **営業準備担当** | 「会社名を1個渡すと、その会社を調べて、提案書と商談の台本まで作って出してきます」 |
| **失注分析担当** | 「商談が流れると、なんで流れたかを分析して『次はこう言え』って台本を直してくるんです。…わりと厳しいんですけど（笑）」 |
| 経理・KPI担当 | 「週次のKPIと月次のPL、AIが勝手に作って出してきます。人間は見るだけです」 |
| オンボーディング担当 | 「助成金の書類も、計画届から支給申請までAIが用意します」 |
| 報告書担当 | 「アンケートを読ませると、次に何を売ればいいかまでAIが見つけてきます」 |

**全12体に共通する、一番強い特徴：**

> 仕事を1回終えるごとに**自分で自分を5軸で採点**し、成功／失敗パターンを記録して、
> 次回はそれを読んでから仕事に入る。5回に1回、自分から状況を報告してくる。

**これが「ツール」ではなく「社員」と呼んでいる根拠。**
ツールは同じことを繰り返す。**社員は前回の反省を持って次に来る。**

→ 名簿と業種別の出し分けは [04_AI社員カタログ.md](04_AI社員カタログ.md)

---

### 判断② 着地は「**採用しなくてよくなる**」

中小企業の社長が今いちばん困っているのは「人が採れない」。
そして採用は「**やって当たり前のこと**」なので、**そもそも必要かを疑ったことがない。**

```
人が足りない → 求人を出す → 採れない/辞める → また求人を出す
                    ↑
        ここしか選択肢がないと思っている
```

**この輪の外側を、質問の形で見せる。**

> **「その仕事って、"人"じゃないとダメですか？」**

こちらが「AIでできますよ」と言うより、**相手が自分で「あ」と思うほうが圧倒的に強い。**

#### ⚠️ 絶対に守る言い分け ── ここを間違えると即切られる

| ✕ 言ってはいけない | ◯ 言う |
|---|---|
| 「**人を減らせます**」 | 「これから**増やさなくて済みます**」 |
| 「人件費を削減できます」 | 「**増員の判断をしなくて済みます**」 |
| 「AIに置き換えます」 | 「**今いる人の手が空きます**」 |

**20〜100名の社長は、社員を家族のように見ている人が多い。**
「AIで人を減らす」はリストラの話に聞こえ、**その瞬間に敵になる。**

> **原則：今いる人には触れない。これから増える予定の1人の話だけをする。**

#### 助成金とも矛盾しない（むしろ整合する）

```
今いる社員が受講者になる（増員はしない）
        ↓
これまで「人を増やして対応していた業務」をAIで処理できるようになる
        ↓
＝「新しい職務に必要な知識・技能の習得」→ 8/3改正の職務直結要件を満たしやすい
```

詳細・想定反論 → [05_採用しないという強み.md](05_採用しないという強み.md)

### 判断③ **相手に質問して話させる。** 目標は相手7割

v4までは一点確認が1箇所だけだった。v5では**6問**に増やし、順番も変えた。

```
v4： AI社員 → 具体例 → 説明拒否 → 質問1つ
v5： AI社員 → 強みの一言 → 質問6つ → 具体例 → 説明拒否
                              ↑
              先に質問すると、相手の状況が分かるので
              出す具体例を選べる。そして自分の課題を
              口にした後だと、具体例が自分ごとになる
```

| # | 質問 | 種類 |
|---|---|---|
| Q1 | 「今も募集出されてますよね。何名くらい探されてるんですか？」 | 事実（答えやすい） |
| Q2 | 「それ、いつ頃から出されてます？」 | 状況（期間が長いほど痛みが確定） |
| **Q3** | **「…けっこう、しんどくないですか？」** | **感情 ← ここで愚痴が出たら勝ち** |
| Q4 | 「1人採れたとして、一人前になるまでどのくらい？」 | 数字 |
| Q5 | 「その間、教える先輩の仕事はどのくらい止まります？」 | 見えていないコスト |
| **Q6** | **「そもそも、その仕事って"人"じゃないとダメですか？」** | **気づき ← 設計の核心** |

#### 話させる4つの作法

1. **質問したら黙る**（心の中で3秒数える。沈黙を埋めない）
2. **答えやすい順に聞く**（事実 → 状況 → 感情 → 数字 → 気づき）
3. **「なぜ」で聞かない**（責めに聞こえる。「いつから」「どのくらい」で聞く）
4. **2問聞いたら1つ返す**（尋問にしない。オウム返しを挟む）

### 判断④ 第2の球として「**引き継ぎ・教育**」を残す

#### なぜここか

| # | 条件 | 引き継ぎ・教育 |
|---|---|---|
| 1 | どの業界にもある | **◎** 人が辞めない会社はない |
| 2 | 社長が痛みを知っている | **◎** ベテラン退職時の最多の懸念は「問題発生時に誰も解決できない」 |
| 3 | 「AIでできるの!?」の意外性 | **◎** 手順ではなく**判断**が移せる、は想像しにくい |
| 4 | ヒダネが実際にやっている | ◎（要・運用確認 → [前提条件](#前提条件)） |
| 5 | **既存ツールと被っていない** | **◎ ここが空いている** |

#### 既存ツールが解決できていない理由

マニュアル作成ツール（Teachme Biz、tebiki 等）は**手順**を残せる。
でも **「どういう時に、どう判断するか」は手順書に書けない**。

```
書ける   ： この機械はこのボタンを押す
書けない ： この客からこの条件で来たら、受けない
書けない ： この症状が出たら、たぶん◯◯が原因
書けない ： この見積は、いつもより1割乗せる
```

**そして「暗黙知の形式知化」は、誰もができていない**（書く時間がないから）。

#### さらに、ヒダネの本業と完全に一致する

**「教える」を売っている研修会社が、「教える」をAI化した話をする。**
これ以上ない整合性。しかも社員3人という規模が、その必然性を証明している。

### 判断⑤ **説明しきらない。** 説明を拒否することがアポになる

電話で全部説明すると「分かった、じゃあいいや」で終わる。**未回収の好奇心だけがアポになる。**

```
STEP 4：「一番説明しづらいのが、そいつら毎回自分で自分の仕事を採点して、
         次から勝手に直してくるところで。
         …電話だとちょっと説明しづらいんですけど。」
                              ↓
                        （焦らす）
                              ↓
STEP 6：「30分だけいただいて、うちのAI社員12人が何やってるか、
         全部お見せします。画面で。」
                              ↓
                        （回収する）
```

**この2つはセット。片方だけだと効かない。**
そして**実際に複雑なので、「電話だと説明しづらい」は嘘ではない。**

### 判断⑥ インパクトは「説明」ではなく「**事実 → 矛盾 → 種明かし**」で作る

```
✕ 「AIで業務を自動化してます」
   → 説明。想像できる。「AIで効率化」の棚に入れられて終わり

◯ 「うち、引き継ぎってものがないんです」            ← ① 不可能に聞こえる事実
   （一拍）
   「人が辞めても、次の人がその日から同じことできます」← ② 矛盾
   「その人の判断の仕方だけ、AIに移してあるので」      ← ③ 種明かし
```

**「AI」という単語を必ず最後に置く。** 先に言うと、相手の頭の中で「またAIの営業か」という既存の棚に分類されてしまう。

そして **「手順書だと書けないんですよ、そこは」** を必ず添える。
既存ツールとの違いを、相手が聞く前に自分から示すため。

### 判断⑦ 受付突破は**2ルートをA/Bで試す**

**どちらが通るかは実際にかけないと分からない。両方使って記録し、比較する。**

| ルート | 文面の入り | 強み | 弱み |
|---|---|---|---|
| **A（安全・実績あり）** | 「御社の求人の件でお電話しました」 | 人事案件は受付の権限外。固有名詞で一斉架電に見えない | AI社員の話へブリッジが1本必要 |
| **B（攻め）** | 「社員3人でAI社員を12人使って会社を回してまして」 | **受付も「え？」となる。判断できないので上げるしかない** | 「怪しい」と弾かれるリスク |

```
架電管理列に「受付ルート（A/B）」を追加し、50件ずつ試して突破率を比較する。
```

**ルートBのリスクを下げる工夫：** 社名を先にはっきり名乗る／「名古屋の」を必ず入れる／
「事例をお話しして回っています」＝ 売り込みではなく共有の体／早口にしない。

ルートAで入った場合は、求人の話（未経験可 → 教えるのは誰？）を1本渡してからAI社員へ繋ぐ。

```
お世話になります。名古屋のヒダネと申します。

御社の求人の件でお電話しました。
Indeedに出されている「製造スタッフ」の募集を拝見しまして、
1つだけお伺いしたいことがあります。

社長さん、いらっしゃいますでしょうか。
```

**求人ルート（A）は、本題への入口としても機能する。**

```
求人に「未経験可」        → 「教えるのは誰がやられてます？」
求人に「経験者優遇/必須」  → 「教える余裕がないから、という感じですか？」
同じ職種を3か月以上掲載    → 「応募が来ないんですか？入っても続かない感じですか？」
```

**3つ目が最強。** どちらに転んでも話が進み、「続かない」なら教育の話にど真ん中で入る。

## 🚨 相手が「社長」か「採用担当」かで、台本を変える

**この設計（v7）は社長専用。** 採用担当にそのまま投げると敵になる。

| | 社長にとって | 採用担当にとって |
|---|---|---|
| 「採用しなくてよくなる」 | **コストが減る朗報** | **自分の仕事がなくなる宣告** |
| 「採用する時代から作る時代へ」 | 経営の話 | **職業そのものの否定** |
| 「増員の判断をしなくて済む」 | 意思決定が楽 | **予算と権限が減る** |

中小企業では**採用担当がゲートキーパーになる**（社長が「採用のことは◯◯に聞いて」と振る）。
**ここで敵を作ると社長に永久に届かない。**

```
受付で「社長」を指名        → 本書（社長ルート）
「採用担当が承ります」と回された → ★即座に 06_採用担当ルート.md へ切り替える
```

**切り替えの合図：**「あ、採用のご担当の方ですか。…求人の原稿って、◯◯さんが書かれてるんですか？」

採用担当ルートの訴求は**まったく別物**：

| ✕ 社長向け | ◎ 採用担当向け |
|---|---|
| 採用しなくてよくなります | **◯◯さんの手が空きます** |
| 御社の社員を1人作らせてください | **求人原稿を1本、AIに書かせてみませんか** |
| （タグライン）採用する時代から作る時代へ | **採用の"作業"を、AIに** |

> **採用担当は「採用したい」わけではない。「採用のノルマから解放されたい」。**
> 解放されたいのは"ノルマ"であって"仕事"ではない。だから**「作業を減らす」**なら味方になる。

詳細 → [06_採用担当ルート.md](06_採用担当ルート.md)

## 自己紹介 ── 誤解を誘発して、訂正で驚かせる

```
弊社、社員を作ってる会社でして。
        （黙る）
→ 相手「人材紹介ですか？」「どういうこと？」

いえ、作るほうです。採用じゃなくて。
        （一拍）
AI社員なんです。うち社員3人しかいないんですけど、AI社員が12人いまして。
```

| 段 | 起きること |
|---|---|
| ①「社員を作ってる会社でして」 | **一言で意味不明。**しかし怪しくはない。相手が必ず何か聞いてくる |
| ②「作るほうです。採用じゃなくて」 | **誤解の訂正。**「採用」との対比が立つ |
| ③「AI社員なんです」 | 種明かし。**ここで初めて「AI」を言う** |

**相手に質問させるのが目的。** こちらが説明を続けるより、相手が「どういうこと？」と聞いてきた形にするほうが、以降ずっと聞いてもらえる。

> ⚠️ **受付には必ず「AI社員」と言う。**「社員を作ってる会社です」だけだと**人材紹介と誤解され、「お断りしてます」で切られる。**
> 誤解を誘うのは社長に出てからだけ。そして**「人材紹介ですか？」には即座に否定する。**曖昧にすると商談で崩れる。

## アポの切り方

> **「御社の社員を1人、作らせてください」**

```
…電話だとちょっと説明しづらいので──

30分だけいただいて、御社の社員を1人、作らせてもらえませんか。

業務を1つ選んでいただければ、それを覚えさせて、そのまま御社で使っていただけます。
無料です。売り込みもしません。
うちがどういう会社かは、それ見てもらうのが一番早いので。
```

| 要素 | 役割 |
|---|---|
| **「作らせてもらえませんか」** | **謙譲。**売り込みではなく「やらせてください」。押していないのに前に出ている |
| 「御社の社員を1人」 | **相手のもの**になる。サンプルではない |
| 「そのまま御社で使っていただけます」 | 成果物が残る。30分が無駄にならない |
| 「うちがどういう会社かは、それ見てもらうのが一番早い」 | **アポの目的が自己紹介になる。**営業ではないと言い切れる |

**「説明できないので、作って見せます」で、拒否が提案に変わる。**
説明を拒否したまま終わるとただの焦らしだが、作る提案に接続すると自然な流れになる。

## ⚠️ 最重要の確認事項 ──「30分で1人作れるのか」

**この台本は「30分で簡易版1体を作って渡せる」ことが前提。** できないのに言うと商談で崩れる。

| ヒダネの実力 | 電話で言う言葉 | 強さ |
|---|---|---|
| **30分で簡易版1体を作って渡せる** | 「**1人作らせてください**」 | **◎ 最強** |
| 30分では完成しないが着手できる | 「1人**作り始めさせて**ください」 | ○ |
| 設計までしかできない | 「どんな社員を作るか、**設計だけ一緒に**やらせてください」 | △ |

**商談側の線引き：** その場で作れるのは**簡易版1体まで**。本格運用には業務の棚卸し・判断基準の言語化・社内展開が要る ── **そこが研修（40万円/人）の価値**。
**電話でも「1人だけ」と明示する。** 後出しで制限をかけると不誠実になる。

**STEP 4 で拒否した説明を、ここで約束する。** 未回収の好奇心が回収される構造。
「1個だけ一緒に選ぶ」は相手の作業が軽く、かつ**職務の特定が終わる**（8/3改正対応）。
