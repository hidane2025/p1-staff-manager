# 03. 刺さる業務カタログ（v3）

> **v2からの変更**
> 選定基準に **条件5「既存ツールの標準機能と被っていないか」** を追加。
> これで球1（応募者への自動返信）と球2（面接の日程調整）が両方とも脱落した。

---

## 球として使える5条件

| # | 条件 | 満たさないとどうなるか |
|---|---|---|
| 1 | どの業界にもある | 業種ごとに台本を作り直すことになる |
| 2 | 社長が痛みを知っている | 受付を突破できない・決裁が動かない |
| 3 | 「AIでできるの!?」の意外性がある | 「AIで効率化」と同じ扱いになり、聞き流される |
| 4 | ヒダネが実際にやっている | 見せてくださいと言われた瞬間に終わる |
| **5** | **既存ツールの標準機能と被っていない** | **「うちもうやってます」で信用ごと失う** |

### 条件5がなぜ致命的か

条件3（意外性）が欠けているだけなら「刺さらなかった」で済む。
**条件5が欠けていると、「この人は何も調べずに電話してきた」と判断される。** 損失の質が違う。

```
社長「それ、うちのATSがもうやってますけど」
     ↓
この電話だけでなく、ヒダネという会社の評価が下がる
```

**架電前に必ず「その業務、既存ツールの標準機能ではないか」を確認する。**

## 既存ツールとの被りチェック表

| 業務 | 既存ツール | 判定 |
|---|---|---|

| 面接の日程調整 | **ATS（カレンダー連携が標準）** | **✕ 標準機能** |

| **求人原稿の作成** | **求人広告代理店（掲載料に含まれる）＋媒体AI**（ビズリーチ「求人自動作成」2025/4 等） | **✕ 二重に埋まっている** |

| 見積書の作成 | 見積ソフト・販売管理システム | ✕ |
| シフト作成 | シフト管理ツール | ✕ |
| 経費精算・請求書処理 | 会計ソフトのOCR | ✕ |
| 手順のマニュアル化 | Teachme Biz、tebiki 等 | **△ 被る** |
| **判断基準の継承** | **なし** | **◎** |
| **新人の「聞ける相手」** | **なし**（社内チャットボットは大企業向け） | **◎** |
| 社内に散らばった情報の検索 | 部分的（大企業向け・高額） | ○ |
| 社長宛メールの下書き | スマートリプライ（業務文脈を持たない） | ○ |

> **無料ATSが普及している**（Airワーク採用管理、リクナビHRTech、Hirehub、yoiwork 等）。
> 「応募者対応をAIで」は、20〜100名の会社でも**既に解決済み**の可能性が高い。

## 球1 ｜引き継ぎ・判断の継承 【主軸】

### 痛みの構造

20〜100名の会社で、社長が夜眠れない理由の上位。

```
ベテランが辞める
      ↓
問題が起きたとき、誰も解決できない  ← 実態調査で最多の懸念
      ↓
品質低下 → 業務停止 → 信用の失墜
```

しかも**本人も何をやっているか言語化できていない**（暗黙知）。
だから引き継ぎ書を書かせても、肝心の「判断」が抜け落ちる。

### 既存ツールが解決できていない理由

マニュアル作成ツール（Teachme Biz、tebiki 等）は**手順**を残せる。
でも **「どういう時に、どう判断するか」は手順書に書けない**。

```
書ける   ： この機械はこのボタンを押す
書けない ： この客からこの条件で来たら、受けない
書けない ： この症状が出たら、たぶん◯◯が原因
書けない ： この見積は、いつもより1割乗せる
```

**ここが空いている。**

### 一言

```
うち社員3人しかいないんですけど、
引き継ぎってものがないんです。

人が辞めても、次の人がその日から同じことできるので。
その人の判断の仕方だけ、AIに移してあるんですよ。
```

### 「え、どうやって？」と聞かれたら

```
本人に作業してもらいながら、横で理由だけ聞いていくんです。
「なんで今それを選んだんですか？」って。

それをAIに覚えさせると、
次の人が同じ場面で「どうすればいい？」と聞いたときに、
その人と同じ答えが返ってくるようになります。

手順書だと書けないんですよ、そこは。
```

### 一点確認

```
今、この人が辞めたら止まるな、って業務ありますか？
→ 「◯◯さんの担当してるところですね」

その方、何年目です？
→ 「20年くらい」

その方が引き継ぎ書を書いたとして、判断のところまで書けそうですか？
→ 「…難しいでしょうね」
```

**最後の質問が効く。** 社長は「引き継ぎ書を書かせればいい」と思っている。
でも**判断は書けない**ことを、聞かれて初めて自覚する。

## 球2 ｜新人の「聞ける相手」

### 痛みの構造

こちらは球1の裏面。**採用した後に何が起きているか**の話。

```
未経験者を採る
      ↓
現場の先輩が教える
      ↓
先輩の仕事が半分止まる（3か月）
      ↓
新人は「何度も聞くと悪い」と思って聞かなくなる
      ↓
分からないまま進めてミスする / 辞める
      ↓
また採用
```

**社長は「採用コスト」は知っているが、「教育中に消えるベテランの工数」は計算していない。**

### 一言

```
うちの新人、先輩に質問しないんですよ。

AIに聞くので。

24時間聞けますし、
同じことを100回聞いても嫌な顔されないので。
```

**「同じことを100回聞いても嫌な顔されない」が効く。**
新人が聞けなくなる理由は「分からないこと」ではなく「**聞きづらいこと**」だから。

### 一点確認

```
新しい方が入って、一人でできるようになるまでどのくらいかかります？
→ 「3か月くらいかな」

その間、教えてる先輩の方は、自分の仕事どのくらい削られてます？
→ 「半分は取られてるかも」

なるほど。じゃあ1人採ると、実質もう1人分の手が3か月消える計算ですね。
```

### この最後の一言が本体

> **「1人採ると、もう1人分の手が3か月消える」**

社長が計算したことのない数字。しかも**新人が3か月で辞めたら、その投資は全部消える**。

## 球3 ｜社内に散らばった情報の検索

### 痛みの構造

「あの時の資料どこだっけ」。紙・Excel・共有フォルダ・個人のメールに散らばっている。
**探している時間は誰も計測していない。**

### 一言

```
うち、過去の見積も図面もやり取りも、全部AIに聞けば出てきます。

「去年の◯◯さんの案件、いくらで出した？」で答えます。
```

### 注意

大企業向けの社内検索製品は存在する（高額）。**「ツールがない」とは言わない。**
「20〜100名の会社が導入できる形でやっている」という言い方にする。

## 球4〜6

| 球 | 一言 | 使いどころ |
|---|---|---|
| **4. クレーム対応の一次返信** | 「クレームの一次返信、AIが書いてます。一番気を使う文章なので、人間が書くと1時間かかるんですよ」 | 対人サービス業。**時間より精神的負荷**を突く |
| **5. 社長宛メールの下書き** | 「社長宛のメール、返信の下書きまでAIが作ってます。社長は読んで直すだけです」 | 社長のメール量が多い会社。**社長自身の時間**が空く |
| **6. 補助金・助成金の申請書類** | 「申請書、AIに書かせてます」 | **電話では使わない。**商談で相手から助成金の話が出たときの補足のみ |

## 球の出し方（v3）

```
STEP 0 の仕込みで求人を確認
        │
        ├─「未経験可」と書いてある ──────→ 球2（聞ける相手）
        │
        ├─「経験者優遇/必須」と書いてある → 球1（引き継ぎ）
        │   ＝ 教える余裕がない証拠
        │
        ├─ 同じ職種を3か月以上出している → 球1 or 球2
        │   「採れてないですか？それとも辞められてます？」で分岐
        │
        └─ 求人を出していない ──────────→ 球1（引き継ぎ）で直接
                                            │
                                            ├─ 刺さった → アポ
                                            └─ 刺さらない → 球3 → ダメなら引く
```

**1回の電話で3球以上投げない。** 4球目は「何か売りたいだけの人」に見える。

---

## 全球共通の型

```
① 不可能に聞こえる事実を先に置く   「うち、引き継ぎってものがないんです」
② 一拍おいて、矛盾を提示する       「人が辞めても、次の人がその日から同じことできます」
③ 種明かしする                     「その人の判断の仕方だけ、AIに移してあるので」
```

**「AI」という単語を、必ず最後に置く。**
