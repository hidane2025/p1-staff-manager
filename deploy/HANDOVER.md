# 引き継ぎ資料（2人目の管理者向け）

**目的**: 中野が不在でも、このシステムを止めずに運用・復旧できる人をもう1名つくる。
**対象**: 伊藤さん（P1 Entertainment 経理）

---

## 1. あなたに持ってもらう権限

| 種類 | 用途 | 渡し方 |
|---|---|---|
| Basic認証（ブラウザの1段階目） | サイトを開くための共通の鍵 | 中野から口頭またはパスワード管理ツールで |
| **個人アカウント**（2段階目） | あなた専用のID・パスワード | **あなた自身が作る**（§2） |
| Railway（サーバー管理画面） | 再起動・ログ確認・設定変更 | 中野がメールアドレスで招待 |
| Supabase（データベース管理画面） | データ確認・バックアップからの復元 | 中野がメールアドレスで招待 |

> **個人アカウントにする理由**: 共有パスワードだと、監査ログに「誰が承認したか」が
> 名前の自己申告でしか残りません。経理システムとして、承認・支払の記録は
> 実在の個人と紐づいている必要があります。

---

## 2. あなた専用のアカウントを作る手順

**パスワードは誰にも教えないでください。中野にも伝える必要はありません。**

1. 中野から共有されたPCで、以下を実行します（お手元のPCでも可）

```bash
python3 scripts/make_app_user.py --username ito --role admin
```

2. パスワードを聞かれるので、あなたが決めたものを入力します（画面には表示されません）
3. `pbkdf2$200000$...` という長い文字列が表示されます。これは**パスワードそのものではなく、
   元に戻せない変換結果**なので、中野に渡しても問題ありません
4. その文字列を中野に渡す → 中野がサーバーに登録 → あなたのIDでログインできるようになります

## 3. あなたが「できるようになっている」べきこと

大会当日、中野と連絡が取れない状況を想定しています。
**[障害対応手順書](RUNBOOK.md) を見ながらで構いません。暗記は不要です。**

- [ ] 公開URLを開き、2段階の認証を通ってホーム画面を表示できる
- [ ] Railwayで「Restart」を押してアプリを再起動できる
- [ ] Railwayで直前の版に戻す（Redeploy）ことができる
- [ ] 当日運用コードを発行し、現場責任者に伝えられる
- [ ] スタッフの領収書リンクを再発行できる
- [ ] Supabaseでバックアップの一覧を開ける（復元の実行は中野の承認が必要）
- [ ] システムが使えないときの**紙運用**に切り替える判断ができる

## 4. このシステムで「やってはいけないこと」

| 禁止 | 理由 |
|---|---|
| 支払済みのデータを直接データベースで書き換える | 監査記録と食い違い、税務上の証跡が壊れる |
| Supabaseのバックアップ復元を単独で実行する | 他事業のデータも同じデータベースにあるため |
| 認証情報をチャット・メールに貼る | 送信履歴に残り、後から回収できない |
| スタッフ用リンク（`?token=` 付き）を他人に転送する | そのリンクだけで本人の領収書が開けてしまう |

---

## 5. 1週間で覚えること（優先順）

1. **日常操作** — 出退勤、支払い計算、承認、封筒リスト（中野と1回通しで実施）
2. **[障害対応手順書](RUNBOOK.md)** — 読むだけでよい。当日は手元に印刷して置く
3. **当日運用コードの発行** — 現場に管理者パスワードを配らないための仕組み
4. **領収書・契約書の配布** — メール送信とQR表示の2経路

システムの内部構造（Docker、nginx、Streamlit等）を理解する必要はありません。
**「止まったら再起動、直らなければ前の版に戻す、それでも駄目なら紙」** が押さえられていれば十分です。
